# Personen zoeken op plaats en onderwerp

**Vraag:** welke personen zijn geboren of overleden in een bepaalde plaats, of hebben met een bepaald onderwerp te maken?

Het endpoint `persons` zoekt personen met filters. Op deze pagina leer je hoe je die filters opbouwt en combineert, wat de API teruggeeft, en hoe je daarna alles over één gevonden persoon ophaalt. Bij elk voorbeeld kun je de filters aanpassen en met **Uitvoeren** het resultaat ophalen en bekijken.

Alle endpoints staan in de [technische API-documentatie](https://data.oorlogsbronnen.nl/services/api/docs).

## Zo bouw je een request

Een request is een gewone `GET` op een URL. Je hebt geen API-sleutel nodig.

```text
https://data.oorlogsbronnen.nl/services/api/persons?birthplace=https://data.niod.nl/WO2_Thesaurus/locations/9881&count=10&offset=0
```

| Parameter    | Waarde                                             | Toelichting                                                                                                |
| ------------ | -------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| `birthplace` | URI of naam van een plaats uit de WO2 Thesaurus    | De geboorteplaats, zoals `https://data.niod.nl/WO2_Thesaurus/locations/9587` of `Utrecht`                  |
| `deathplace` | URI of naam van een plaats uit de WO2 Thesaurus    | De plaats van overlijden                                                                                   |
| `keywords`   | URI of naam van een onderwerp uit de WO2 Thesaurus | Een trefwoord dat aan de persoon is gekoppeld, zoals `https://data.niod.nl/WO2_Thesaurus/2657` of `verzet` |
| `count`      | 1 tot en met 50, standaard 10                      | Hoeveel resultaten je wilt ontvangen                                                                       |
| `offset`     | 0 tot en met 300, standaard 0                      | Hoeveel resultaten je overslaat, om te bladeren                                                            |

Voor de filters gelden dezelfde vier regels als bij [Objecten zoeken](./objecten):

- **Minstens één filter is verplicht.** Zonder filter geeft de API een foutmelding (`HTTP 400`).
- **Gebruik een URI of een naam.** Een naam moet precies overeenkomen met een naam van de term in de WO2 Thesaurus: het voorkeurslabel (`prefLabel`) of een alternatieve of verborgen naam (`altLabel`, `hiddenLabel`). Hoofdletters maken niet uit. `birthplace=utrecht` werkt dus net zo goed als de URI. Wijkt de naam af, of geef je alleen het nummer van de URI, dan krijg je geen foutmelding maar een lege lijst.
- **Dezelfde parameter herhalen betekent OF.** `?deathplace=A&deathplace=B` geeft personen die in A of in B zijn overleden.
- **Verschillende filters combineren betekent EN.** `?birthplace=A&keywords=C` geeft personen die in A zijn geboren en trefwoord C hebben.

## Plaatsen en onderwerpen opzoeken

Plaatsen en onderwerpen komen allebei uit de WO2 Thesaurus. Kampen hebben een eigen deel van de thesaurus, met `/kampen/` in de URI. In een filter mag je de URI of de naam gebruiken. Een URI wijst altijd precies één term aan; met een naam hoef je de URI niet op te zoeken. De voorbeelden op deze pagina gebruiken deze termen:

| URI                                                 | Naam      |
| --------------------------------------------------- | --------- |
| `https://data.niod.nl/WO2_Thesaurus/locations/9577` | Amsterdam |
| `https://data.niod.nl/WO2_Thesaurus/locations/9881` | Haarlem   |
| `https://data.niod.nl/WO2_Thesaurus/locations/9576` | Rotterdam |
| `https://data.niod.nl/WO2_Thesaurus/kampen/3653`    | Auschwitz |
| `https://data.niod.nl/WO2_Thesaurus/kampen/4855`    | Sobibor   |
| `https://data.niod.nl/WO2_Thesaurus/2657`           | Verzet    |
| `https://data.niod.nl/WO2_Thesaurus/2244`           | N.S.B.    |

De URI van een andere plaats zoek je op naam met deze query. Vervang `haarlem` door de plaats die je zoekt.

<SparqlEditor
  query={`PREFIX skos: <http://www.w3.org/2004/02/skos/core#>
SELECT ?plaats ?naam WHERE {
  ?plaats skos:prefLabel ?naam .
  FILTER(LCASE(STR(?naam)) = "haarlem")
  FILTER(STRSTARTS(STR(?plaats), "https://data.niod.nl/WO2_Thesaurus/"))
}`}
/>

Welke namen je voor een term in een filter kunt gebruiken, zie je met de query hieronder. Die toont alle namen van de N.S.B., zoals `NSB` en `Nationaal Socialistische Beweging`. Vervang de URI door die van de term die je zoekt.

<SparqlEditor
  query={`PREFIX skos: <http://www.w3.org/2004/02/skos/core#>
SELECT ?soort ?naam WHERE {
  VALUES ?soort { skos:prefLabel skos:altLabel skos:hiddenLabel }
  <https://data.niod.nl/WO2_Thesaurus/2244> ?soort ?naam .
}`}
/>

## Zo ziet een response eruit

De response heeft dezelfde vorm als bij de andere endpoints. Elk resultaat staat in `items[n].tuple[0]`, en bijna elk veld is een lijst. Omdat je een lijst van personen krijgt, staan per persoon alleen de basisgegevens erin:

```json
{
  "offset": 0,
  "count": 10,
  "items": [
    {
      "rank": 28,
      "probability": 1,
      "tuple": [
        {
          "id": "https://n2t.net/ark:/59857/p17bffd61-a9c2-476c-83db-0d7a1f04112b",
          "name": ["Nicolaas Bernardus Peeters"],
          "alternateName": ["Nicolaas Bernardus Peeters"],
          "birthDate": ["1893-04-12"],
          "birthPlace": ["'s-Hertogenbosch"],
          "deathDate": ["1945-02-21"],
          "deathPlace": ["Dachau"],
          "deceased": ["true"],
          "type": [
            "https://personsincontext.org/model#PersonReconstruction",
            "https://schema.org/Person"
          ]
        }
      ]
    }
  ]
}
```

| Veld                      | Betekenis                                                                                                                                                    |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `id`                      | De persistente ARK-link van de persoonsreconstructie. De UUID aan het eind, zonder de `p` ervoor, heb je voor de [vervolgaanroepen](#vervolgaanroepen) nodig |
| `name`, `alternateName`   | Naam en andere schrijfwijzen                                                                                                                                 |
| `birthDate`, `birthPlace` | Geboortedatum (`JJJJ-MM-DD`) en -plaats                                                                                                                      |
| `deathDate`, `deathPlace` | Overlijdensdatum en -plaats                                                                                                                                  |
| `deceased`                | `"true"` als bekend is dat de persoon is overleden, ook als de datum ontbreekt                                                                               |
| `type`                    | Altijd een persoonsreconstructie (`PersonReconstruction`) en een `https://schema.org/Person`                                                                 |

Familie, trefwoorden, de vermeldingen per bron en de gebeurtenissen daarin staan niet in deze response. Die haal je per persoon op met [`person`](#vervolgaanroepen).

Let op twee dingen:

- **De plaatsen in de response zijn tekst**, zoals `"Haarlem"`, en geen URI. Die tekst komt uit de bron en is niet altijd een naam uit de thesaurus. Gebruik hem dus niet zonder meer als filter.
- **Er zitten geen foto's in de response.** De visualisatie toont daarom een vervangende afbeelding.

Net als bij de andere endpoints is `count` het aantal dat je hebt gevraagd en niet het totaal. Krijg je minder resultaten dan je vroeg, dan ben je aan het eind. Een lege `items`-lijst betekent dat er niemand past bij deze combinatie van filters.

## Eén filter

Personen die in Haarlem zijn geboren, hier gefilterd met de URI. Vervang die door `haarlem` en klik op **Uitvoeren**: je krijgt hetzelfde resultaat. Maak het veld `birthplace` leeg en klik op **Uitvoeren** om de foutmelding te zien die je krijgt als er geen filter is.

<ApiRequest
  endpoint="/persons"
  query={{
    birthplace: ["https://data.niod.nl/WO2_Thesaurus/locations/9881"],
    deathplace: [],
    keywords: [],
    count: 10,
    offset: 0,
  }}
/>

## Meerdere plaatsen (OF)

Personen die in Sobibor **of** in Auschwitz zijn overleden. Met **+ waarde toevoegen** zet je er nog een plaats bij. In de URL zie je dat `deathplace` dan nog een keer voorkomt.

<ApiRequest
  endpoint="/persons"
  query={{
    birthplace: [],
    deathplace: [
      "https://data.niod.nl/WO2_Thesaurus/kampen/4855",
      "https://data.niod.nl/WO2_Thesaurus/kampen/3653",
    ],
    keywords: [],
    count: 10,
    offset: 0,
  }}
/>

## Plaats en onderwerp (EN)

Personen die in Haarlem zijn geboren **en** het trefwoord Verzet hebben, onder wie Hannie Schaft. Dit voorbeeld filtert met namen in plaats van URI's. Probeer ook `keywords` te vervangen door `nsb` of door de URI `https://data.niod.nl/WO2_Thesaurus/2244`.

<ApiRequest

    count: 10,
    offset: 0,
  }}
/>

## Meer over een gevonden persoon {#vervolgaanroepen}

`persons` geeft per persoon alleen de basisgegevens. Met de ID van de persoon haal je de rest op. Dat is de UUID aan het eind van `id`, zonder de `p` ervoor: bij `https://n2t.net/ark:/59857/p48968c01-9f60-492d-8712-58d3b8c2b388` is dat `48968c01-9f60-492d-8712-58d3b8c2b388`. De hele ARK-link werkt ook, maar de UUID met de `p` ervoor geeft een lege lijst.

| Endpoint                       | Je krijgt                                                                                                 |
| ------------------------------ | --------------------------------------------------------------------------------------------------------- |
| `/person/p/id/{id}`            | Het profiel met familierelaties en trefwoorden, plus de vermeldingen per bron en de gebeurtenissen daarin |
| `/person_related_objects/{id}` | Gekoppelde foto's en objecten uit collecties                                                              |

Deze twee endpoints worden uitgelegd in het cookbook [Alles over een persoon](./persoon). Op elke kaart hierboven staat de link **Alles over deze persoon**.

```js
const base = "https://data.oorlogsbronnen.nl/services/api";

// append() voegt een waarde toe; herhaal het voor meerdere waardes (OF).
const params = new URLSearchParams();
params.append(
  "birthplace",
  "https://data.niod.nl/WO2_Thesaurus/locations/9881",
);
params.append("keywords", "https://data.niod.nl/WO2_Thesaurus/2657");
params.append("count", "50");

async function haalOp(url) {
  const res = await fetch(url);
  if (!res.ok) throw new Error(`HTTP ${res.status} bij ${url}`);
  const { items } = await res.json();
  return items.map((item) => item.tuple[0]);
}

const personen = await haalOp(`${base}/persons?${params}`);
console.log(personen.length, "personen gevonden");

// De UUID staat aan het eind van de ARK-link, na de "p".
// Haal het profiel op; doe vervolgaanroepen na elkaar, niet tegelijk.
const persoon = personen[0];
const uuid = persoon.id.match(/p([0-9a-f-]{36})$/)[1];
const [profiel] = await haalOp(`${base}/person/p/id/${uuid}`);

// Gebeurtenissen zitten in de vermeldingen: wasDerivedFrom[].actor[]
const gebeurtenissen = profiel.wasDerivedFrom.flatMap((v) => v.actor);
console.log(persoon.name[0], "heeft", gebeurtenissen.length, "gebeurtenissen");
```

```python
import requests

BASE = "https://data.oorlogsbronnen.nl/services/api"


def zoek_personen(filters):
    """Haalt alle pagina's op, tot de API minder dan 50 resultaten geeft."""
    personen = []
    for offset in range(0, 301, 50):
        params = {**filters, "count": 50, "offset": offset}
        res = requests.get(f"{BASE}/persons", params=params, timeout=30)
        res.raise_for_status()
        items = res.json()["items"]
        personen += [item["tuple"][0] for item in items]
        if len(items) < 50:
            break
    return personen


# Een lijst wordt een herhaalde parameter: overleden in Sobibor OF Auschwitz
personen = zoek_personen({
    "deathplace": [
        "https://data.niod.nl/WO2_Thesaurus/kampen/4855",
        "https://data.niod.nl/WO2_Thesaurus/kampen/3653",
    ],
})
for persoon in personen[:5]:
    # De UUID staat aan het eind van de ARK-link, na de "p".
    uuid = persoon["id"].rsplit("/p", 1)[-1]
    print(uuid, persoon["name"][0])
```

:::caution[Gebruik in de browser]

De API stuurt geen CORS-headers. Een webapplicatie op een ander domein kan de API daarom niet rechtstreeks aanroepen. Roep de API aan vanaf je eigen server of via een proxy. Vanaf de command line, in Python en in Node.js speelt dit niet.

:::

## Verder bouwen

- **Meer dan 50 resultaten:** verhoog `offset` met `count` (0, 50, 100, …). De hoogste `offset` is 300, dus je kunt maximaal 350 resultaten per zoekvraag ophalen. Heb je er meer nodig, maak de zoekvraag dan kleiner met een extra filter.
- **Verzoeken na elkaar:** de API geeft op dit moment regelmatig `HTTP 500` als je verzoeken tegelijk doet. Doe ze na elkaar, zoals in de voorbeelden, en probeer het bij zo'n fout opnieuw.
- **Objecten over hetzelfde onderwerp:** met dezelfde thesaurus-URI's zoek je in [Objecten zoeken](./objecten) naar foto's en archiefstukken.

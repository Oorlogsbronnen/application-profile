# Alles over een persoon ophalen

**Vraag:** je hebt de ID van een persoon. Wie was dit, wat is er gebeurd, welke bronnen noemen deze persoon en welke foto's en documenten horen erbij?

Twee endpoints van de Oorlogsbronnen-API geven samen antwoord. `person` geeft in één response het profiel van de persoon, alle bronnen die de persoon noemen en de gebeurtenissen uit die bronnen. `person_related_objects` geeft de foto's en documenten uit collecties. Het voorbeeld is verzetsstrijder Hannie Schaft. Alle endpoints staan in de [technische API-documentatie](https://data.oorlogsbronnen.nl/services/api/docs).

Op deze pagina loop je de response van `person` in drie stappen door. Elke stap licht een ander deel van dezelfde response toe. Bij elke stap kun je het request aanpassen en met **Uitvoeren** het resultaat ophalen. Het overzicht toont dan alleen het deel dat bij die stap hoort; onder **JSON** zie je steeds de volledige response.

| Je wilt weten | Waar in de response | Je krijgt |
| --- | --- | --- |
| Wie was deze persoon? | [`person`, het profiel](#person) | Eén samengevoegd profiel met biografie, familie en trefwoorden |
| Wat is er gebeurd? | [`person`, de gebeurtenissen](#gebeurtenissen) | Gebeurtenissen zoals arrestatie en overlijden, per bron |
| Wat zegt elke bron? | [`person`, de vermeldingen](#vermeldingen) | De vermelding van de persoon in elke afzonderlijke bron |
| Welk materiaal hoort erbij? | [`person_related_objects`](#person_related_objects) | Foto's, documenten en andere objecten uit collecties |

## Reconstructie en vermelding

De API maakt onderscheid tussen twee dingen:

- Een **[persoonsvermelding](/schema#PersoonsvermeldingShape)** is wat één bron over iemand zegt. Bronnen kunnen elkaar tegenspreken: Hannie Schaft staat bij de ene bron als geboren in Haarlem en bij de andere in Bloemendaal.
- Een **[persoonsreconstructie](/schema#PersoonsReconstructieShape)** is het samengevoegde profiel dat op die vermeldingen is gebaseerd. De ID die je aan de API geeft, is altijd de ID van de reconstructie.

De response van `person` volgt die opbouw. Bovenaan staat de reconstructie. Daarin staan in `wasDerivedFrom` de vermeldingen waarop die is gebaseerd, en in elke vermelding staan in `actor` de [gebeurtenissen](/schema#EventShape) die die bron noemt:

```text
items[0].tuple[0]                  de persoonsreconstructie (stap 1)
└─ wasDerivedFrom[]                de persoonsvermeldingen (stap 3)
   └─ actor[]                      de gebeurtenissen per vermelding (stap 2)
```

## Zo bouw je een request

Een request is een gewone `GET` op een URL. Je hebt geen API-sleutel nodig.

```text
https://data.oorlogsbronnen.nl/services/api/person/p/id/48968c01-9f60-492d-8712-58d3b8c2b388
└───────────────── basis-URL ──────────────┘└─ endpoint ─┘└──────────────── ID ───────────────┘
```

| Deel | Waarde | Toelichting |
| --- | --- | --- |
| Basis-URL | `https://data.oorlogsbronnen.nl/services/api` | Is voor alle endpoints gelijk |
| Endpoint en ID | `/person/p/id/{id}`<br/>`/person_related_objects/{id}` | Let op: het pad van `person` is anders dan dat van `person_related_objects` |
| `count` | 1 tot en met 50, standaard 10 | Alleen bij `person_related_objects`: hoeveel objecten je wilt ontvangen |
| `offset` | 0 tot en met 300, standaard 0 | Alleen bij `person_related_objects`: hoeveel objecten je overslaat, om te bladeren |

De ID is een UUID. Je vindt die aan het eind van de persistente link van een persoon, zonder de `p` ervoor. Bij `https://n2t.net/ark:/59857/p48968c01-9f60-492d-8712-58d3b8c2b388` is de ID dus `48968c01-9f60-492d-8712-58d3b8c2b388`.

## Zo ziet een response eruit

Beide endpoints geven JSON-LD terug in dezelfde vorm. Het resultaat zelf staat steeds in `items[n].tuple[0]`:

```json
{
  "@context": { "@vocab": "https://personsincontext.org/model#" },
  "offset": 0,
  "count": 10,
  "items": [
    {
      "rank": 1,
      "probability": 1.0,
      "tuple": [
        {
          "id": "https://n2t.net/ark:/59857/p48968c01-9f60-492d-8712-58d3b8c2b388",
          "name": ["Hannie Schaft"],
          "birthDate": ["1920-09-16"],
          "spouse": [],
          "wasDerivedFrom": [
            {
              "name": ["Jannetje Johanna Schaft"],
              "actor": [{ "name": ["Omgekomen"], "startDate": ["1945-04-17"] }]
            }
          ]
        }
      ]
    }
  ]
}
```

Houd bij het verwerken rekening met het volgende:

- **Bijna elk veld is een lijst**, ook als er maar één waarde is. Een veld zonder waarde is een lege lijst (`[]`).
- **`person` geeft altijd alles in één keer.** De vermeldingen en gebeurtenissen zijn niet gepagineerd: je krijgt ze allemaal, ongeacht `count`.
- **Bij `person_related_objects` is `count` niet het totaal.** Het is het aantal dat je hebt gevraagd. De API meldt niet hoeveel resultaten er in totaal zijn. Verhoog `offset` met `count` tot je minder resultaten krijgt dan je vroeg.
- **Een onbekende ID geeft geen foutmelding**, maar `HTTP 200` met een lege `items`-lijst. Alleen een ongeldige `count` of `offset` geeft een fout (`HTTP 422`).
- **Doe verzoeken na elkaar, niet tegelijk.** Bij gelijktijdige verzoeken geeft de API op dit moment regelmatig `HTTP 500`. Probeer het bij zo'n fout gewoon opnieuw.

## Stap 1: het profiel {#person}

Het bovenste niveau van de response is de persoonsreconstructie: de samengevoegde gegevens van één persoon. Het overzicht toont hier alleen dat profiel.

<ApiRequest
  endpoint="/person/p/id/{id}"
  pathParams={{ id: "48968c01-9f60-492d-8712-58d3b8c2b388" }}
  query={{}}
  view="person"
/>

| Veld | Betekenis |
| --- | --- |
| `name`, `alternateName` | Naam en andere schrijfwijzen |
| `birthDate`, `birthPlace` | Geboortedatum (`JJJJ-MM-DD`) en -plaats |
| `deathDate`, `deathPlace` | Overlijdensdatum en -plaats |
| `gender` | Geslacht als schema.org-term, zoals `https://schema.org/Female` |
| `parent`, `spouse`, `children` | Familieleden met hun ARK-link (`id`), naam en levensdata. Haal de ID uit de link om hun profiel op te vragen |
| `keywords` | Trefwoorden uit de WO2 Thesaurus, met een label per taal in `prefLabel` |
| `sameAs` | Dezelfde persoon op een andere website, zoals Wikipedia |
| `id` | De persistente ARK-link. De UUID aan het eind is de ID |
| `wasDerivedFrom` | De persoonsvermeldingen, met daarin de gebeurtenissen. Zie stap 2 en 3 |

Hannie Schaft heeft geen familierelaties in de data. Wil je die zien? Vul dan de ID `5b4e704c-507b-403f-b1bf-08c146322441` in en klik op **Uitvoeren**.

## Stap 2: wat er gebeurde {#gebeurtenissen}

Dezelfde response bevat ook de gebeurtenissen in het leven van de persoon, zoals een arrestatie of overlijden. Ze staan niet op het hoogste niveau, maar in de vermelding waar ze vandaan komen: `wasDerivedFrom[n].actor`. Gebeurtenissen worden dus niet samengevoegd: noemen meerdere bronnen het overlijden van Hannie Schaft, dan krijg je meerdere gebeurtenissen. Het overzicht hieronder haalt ze uit alle vermeldingen bij elkaar en toont ze als tijdlijn, met gebeurtenissen van dezelfde datum onder elkaar.

<ApiRequest
  endpoint="/person/p/id/{id}"
  pathParams={{ id: "48968c01-9f60-492d-8712-58d3b8c2b388" }}
  query={{}}
  view="events"
/>

| Veld | Betekenis |
| --- | --- |
| `name` | Beschrijving van de gebeurtenis, zoals `Gearresteerd in Haarlem/op straat` |
| `additionalType` | Soort gebeurtenis als thesaurusterm, zoals `Gearresteerd` of `Overleden` |
| `startDate`, `endDate` | Wanneer het gebeurde. Dit kan ontbreken |
| `location`, `fromLocation`, `toLocation` | Waar het gebeurde, of het begin en einde van een reis of transport, als term uit de WO2 Thesaurus |
| `location_str`, `fromLocation_str`, `toLocation_str` | Dezelfde plaatsen als tekst, zoals de bron ze noemt. Vaak gevuld als er geen thesaurusterm is |
| `description` | Toelichting, zoals een doodsoorzaak |

Een gebeurtenis heeft geen eigen bronvermelding. De bron staat in `hadPrimarySource` van de vermelding waar de gebeurtenis in staat (zie stap 3).

De gebeurtenissen staan niet op datum. Sorteer ze zelf op `startDate` als je een tijdlijn wilt maken. Bij Hannie Schaft zijn het er 14, verdeeld over 11 vermeldingen.

## Stap 3: wat elke bron zegt {#vermeldingen}

Het laatste deel van de response is `wasDerivedFrom`: alle persoonsvermeldingen waarop het profiel is gebaseerd. Zo zie je wat elke bron meldt en waar de bron te vinden is. Foto's van de persoon staan ook hier, in `image`, en niet op het hoogste niveau van het profiel. Het overzicht toont één kaart per vermelding.

<ApiRequest
  endpoint="/person/p/id/{id}"
  pathParams={{ id: "48968c01-9f60-492d-8712-58d3b8c2b388" }}
  query={{}}
  view="observations"
/>

| Veld | Betekenis |
| --- | --- |
| `name`, `givenName`, `familyName`, `initials`, `alternateName` | De naam zoals de bron die noemt |
| `birthDate`, `birthPlace`, `deathDate`, `deathPlace` | De levensgegevens volgens deze bron |
| `jobTitle`, `homeLocation` | Beroep en woonplaats |
| `description` | Beschrijving uit de bron. Deze kan HTML bevatten |
| `image` | Afbeeldingen met `thumbnailUrl` en `caption` |
| `keywords` | Trefwoorden uit de WO2 Thesaurus |
| `actor` | De gebeurtenissen die deze bron noemt. Zie stap 2 |
| `hadPrimarySource` | De bron. `url` is de link naar het record bij de bron en kan leeg zijn. `id` is een identifier en werkt niet altijd als link |

## `person_related_objects`: foto's en documenten {#person_related_objects}

Dit tweede endpoint geeft historische foto's, krantenknipsels en andere objecten uit WO2-collecties die aan de persoon zijn gekoppeld. Veel personen hebben geen gekoppelde objecten. Je krijgt dan een lege `items`-lijst.

<ApiRequest
  endpoint="/person_related_objects/{id}"
  pathParams={{ id: "48968c01-9f60-492d-8712-58d3b8c2b388" }}
/>

| Veld | Betekenis |
| --- | --- |
| `name`, `description` | Titel en beschrijving |
| `additionalType` | Soort object, zoals `krantenknipsel` of `still image` |
| `dateCreated`, `startDate`, `endDate` | Wanneer het object is gemaakt of waarop het betrekking heeft |
| `thumbnailUrl`, `contentUrl` | De afbeelding, als die beschikbaar is |
| `url` | De pagina van het object bij de collectie |
| `publisher`, `provider`, `isPartOf` | De organisatie en collectie waar het object vandaan komt |
| `about`, `keywords`, `contentLocation` | Waar het object over gaat: personen, onderwerpen en plaatsen |
| `license` | De rechten op dit object |

Controleer `license` voordat je een object hergebruikt. Sommige objecten zijn auteursrechtelijk beschermd. Meer hierover lees je bij [rechten en gebruik](/rechten-en-gebruik).

## In je eigen code

Deze voorbeelden halen alles op over één persoon: het profiel met vermeldingen en gebeurtenissen, en de gekoppelde objecten.

  <TabItem value="js" label="JavaScript">

```js
const base = "https://data.oorlogsbronnen.nl/services/api";
const id = "48968c01-9f60-492d-8712-58d3b8c2b388";

async function haalOp(pad) {
  const res = await fetch(`${base}${pad}`);
  if (!res.ok) throw new Error(`HTTP ${res.status} bij ${pad}`);
  const { items } = await res.json();
  return items.map((item) => item.tuple[0]);
}

// Na elkaar, niet tegelijk: zie de opmerking over gelijktijdige verzoeken hierboven.
const [persoon] = await haalOp(`/person/p/id/${id}`);
const objecten = await haalOp(`/person_related_objects/${id}?count=50`);

// Stap 3: de vermeldingen. Stap 2: de gebeurtenissen daarin, met de bron erbij.
const vermeldingen = persoon.wasDerivedFrom;
const gebeurtenissen = vermeldingen
  .flatMap((v) => v.actor.map((g) => ({ ...g, bron: v.hadPrimarySource })))
  .sort((a, b) => (a.startDate[0] ?? "9999").localeCompare(b.startDate[0] ?? "9999"));

console.log(persoon.name[0], gebeurtenissen.length, vermeldingen.length, objecten.length);
```

  </TabItem>
  <TabItem value="python" label="Python">

```python
import requests

BASE = "https://data.oorlogsbronnen.nl/services/api"
ID = "48968c01-9f60-492d-8712-58d3b8c2b388"


def haal_op(pad, **params):
    res = requests.get(f"{BASE}{pad}", params=params, timeout=30)
    res.raise_for_status()
    return [item["tuple"][0] for item in res.json()["items"]]


persoon = haal_op(f"/person/p/id/{ID}")[0]
objecten = haal_op(f"/person_related_objects/{ID}", count=50)

# Stap 3: de vermeldingen. Stap 2: de gebeurtenissen daarin, met de bron erbij.
vermeldingen = persoon["wasDerivedFrom"]
gebeurtenissen = sorted(
    ({**g, "bron": v["hadPrimarySource"]} for v in vermeldingen for g in v["actor"]),
    key=lambda g: (g["startDate"] or ["9999"])[0],
)

print(persoon["name"][0], len(gebeurtenissen), len(vermeldingen), len(objecten))
```

:::caution[Gebruik in de browser]

De API stuurt geen CORS-headers. Een webapplicatie op een ander domein kan de API daarom niet rechtstreeks aanroepen. Roep de API aan vanaf je eigen server of via een proxy. Vanaf de command line, in Python en in Node.js speelt dit niet.

:::

## Verder bouwen

- **Andere persoon:** vervang de ID in het pad. De rest van de URL blijft hetzelfde. Een ID vind je met [Personen zoeken](./personen).
- **Meer dan 50 objecten:** verhoog bij `person_related_objects` de `offset` met `count` (0, 50, 100, …). De hoogste `offset` is 300, dus je kunt maximaal 350 objecten ophalen.
- **Hetzelfde met SPARQL:** op de pagina over [SPARQL](../services/sparql.mdx) staan voorbeeldqueries, onder andere voor een tijdlijn.
